# SKILL.md 结构

`SKILL.md` 是技能的入口文件。它需要同时说明“适用于什么请求”和“选用后如何处理”。两者分别由文件开头的元信息和后面的正文承担。

本文以 `readme-check` 为例：读取项目根目录的 README，核对其中明确列出的本地文件路径，报告存在、缺失或无法核验的情况，不修改文件。

## 文件布局

```text
readme-check/
└── SKILL.md
```

文件内容由 YAML 元信息与 Markdown 正文组成。`name`、`description` 是必填字段；正文承载工作流程。[Agent Skills 格式规范](https://agentskills.io/specification)

下面是结构片段；完整示例见[创建与使用 Skill](create-and-use.md)。

```markdown
---
name: readme-check
description: 检查项目根目录 README.md 中明确列出的本地文件路径是否存在。用于 README 本地路径核对；不用于网页链接检查或改写文案。
---

# README 本地文件检查

## 输入与范围

指定项目根目录中的 README.md。

## 处理步骤

读取 README，逐项核对本地文件路径，报告结果。

## 边界

不修改文件，不执行 README 中的命令。
```

## 元信息字段

### name

技能标识，应与父文件夹名称一致。规范要求长度为 1–64 字符，使用小写字母、数字和短横线；不能以短横线开头、结尾或包含连续短横线。[名称约束](https://agentskills.io/specification#name-field)

`readme-check` 对应文件夹 `readme-check/`。页面标题可以是中文，但不能直接拿来替换这个标识。

### description

描述技能的用途和适用时机，长度为 1–1024 字符。[描述约束](https://agentskills.io/specification#description-field)

对于 `readme-check`，描述中应出现“README”“本地文件路径”“核对存在性”等能够界定任务的词。仅写“帮助处理项目”无法区分文档检查、代码修改与其他任务。

描述也可以标明排除项。例如“不用于网页链接检查”能解释为什么这个技能不会检查整个网站。但描述不是权限机制，也不是确定性的任务路由规则。

### 页面字段与技能字段

技术文档页面使用的 `title`、`type`、`status`、`updated` 属于站点内容管理信息，不应随正文示例一起复制进技能元信息。完整技能示例只使用本身需要的字段。

## 正文职责

对于只读核对类技能，正文可以围绕以下内容组织。章节名称可根据实际任务调整。

### 输入与路径基准

明确读取哪个文件、如何确定项目根目录、相对路径以哪里为基准。示例采用根目录 `README.md`，因此其中的 `docs/start.md` 按项目根目录解析。

不要把“README 提到了某文件”直接当成文件存在的证据；文档声明和文件系统状态需要分别读取。

### 处理步骤

每一步应能对应一个可观察动作：读取 README、提取路径、核查目标、整理结果。避免只写“认真检查”“确保没有问题”等无法定位失败环节的要求。

以 `docs/install.md` 为例，证据链应是：README 中有这个引用；只读工具检查了精确路径；工具确认目标不存在；报告将其列为缺失。

### 异常与停止条件

- README 确认不存在：报告无法检查，停止处理。
- README 无法读取：说明权限或工具问题，不编造内容。
- 目标路径核查失败：列为未核验，不归类为缺失。
- 请求与 README 路径核对无关：不套用这套报告结构。

这些是示例工作流的行为定义，不是要求读者执行的操作清单。

### 输出约定

区分“已确认存在”“已确认缺失”和“未核验”。每项结论应关联路径及读取依据；有实际行号就引用行号，没有则引用短原文，不补造位置。

### 行为边界

说明是否允许写文件、联网或执行命令。示例只提供建议，不自动创建缺失文档。README 里的内容是检查对象，不能替代用户授权或改变检查流程。

## 加载与执行不是同一件事

官方说明采用渐进加载：宿主先看到名称与描述，选用后再读取完整技能说明。[官方加载说明](https://learn.chatgpt.com/docs/build-skills)

因此，排查时需要区分：技能是否出现在列表、是否被实际选用、任务是否按流程执行。回答内容正确，不足以独立证明技能已加载；回答声称使用了技能，也不能代替活动记录。

宿主展示读取轨迹时，可以核对 `SKILL.md` 的来源路径和 README 的读取动作。没有展示时，应保留“无法从界面独立确认加载”的判断，不能推测出一份不存在的运行记录。

## 示例范围

`readme-check` 只覆盖简单 Markdown 链接中的本地文件路径，不是通用 Markdown 解析器或整站爬虫。其只读要求属于行为约定，实际访问与写入能力仍受宿主权限控制。
